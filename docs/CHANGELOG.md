## 2026-10-24 · v2.0.17 复原休息模块（回到 v2.0.14 的行为）

来源：腾讯文档《专注小站迭代log》v2.0.16 页第 2 条（原文指定解包 `artifacts/FocusStation-v2.0.14-dev.exe` 复原休息模块）。

- **问题**：v2.0.16 把番茄钟到点改成了「不暂停、超时继续计时、只响一声」，方向理解错了。用户要的是回到 v2.0.14 的样子。
- **证据**：直接对 4 个安装包做字节级比对（UTF-16LE 字符串扫描），v2.0.13 / v2.0.14 / v2.0.15 都包含「到休息时间了」「计时已暂停」「继续专注 5 分钟」「休息提醒」「已经连续专注」「当前子任务到点自动暂停」，v2.0.16 里这批文案全部消失——确实是 v2.0.16 改坏的。
- **复原内容（逐条对齐 v2.0.14）**：
  - `FocusEngine.Tick()` 番茄钟到点：恢复 `ReminderSent=true; State=Phase.Paused; return "due"`，并把计时卡在到点那一刻（超时部分不计入专注时长）。
  - `FocusEngine.Tick()` 挑战模式：恢复「连续专注 N 分钟」→ `State=Phase.Paused; return "challenge-break"`。
  - `MainForm.HandleEvent`：恢复 `due` 弹窗（到休息时间了 / 开始休息 / 继续专注 5 分钟 / 结束本次）与 `challenge-break` 弹窗（开始休息 / 继续挑战 / 保持暂停）。
  - `MainForm.PauseResume`：恢复点「继续」时 `Snooze()`（自动再给 5 分钟）。
  - `RefreshDisplay`：恢复「已到休息时间 · 等待确认」「当前子任务到点自动暂停，确认后才进入休息。」，去掉「超时 MM:SS」。
  - 删除 v2.0.16 引入的 `StageOvertimeSeconds` / `RestDue` 两个属性。
- **保留 v2.0.16 的另一条**：已完成列表按完成时间倒序（`CompletedUtc`）不受影响。
- **结果**：到点就暂停并弹窗确认；不点「开始休息」永远不会进入休息，休息也不会被自动开启。

## 2026-10-23 · v2.0.14 时间统计口径修正 + 模板按钮（下拉 / 长按编辑）

来源：腾讯文档《专注小站迭代log》v2.0.14 页，两条反馈。

- **① 项目时间统计不对（从未开始的项目也显示 4 小时）**
  - 根因：v2.0.13 里括号中的数字用的是「项目设定的总时长」（挑战分钟 / 番茄分钟 / 全局默认），并不是真实专注记录。一个从没开始过的项目，设定 240 分钟就会显示成 4 小时，看起来像统计数据。
  - 改为：括号里一律是**该项目累计真实专注时长**（`TimeRecord.Seconds` 全量求和，含今天；兼容早年 ProjectId 为空、只记了项目名的旧记录）。
    - 今天有记录 / 正在专注：`今日已专注：今日时长（累计时长）`
    - 今天没有记录：`项目总专注：累计时长（今日没有记录噢）`
  - 从未开始的项目因此显示 `项目总专注：00:00:00（今日没有记录噢）`，不再凭空冒出设定时长。
  - `TaskSupport.ProjectTotalSeconds` 保留（表达「设定总时长」这个另一个口径），但不再参与这条文案，避免两个概念混用。
- **② 写稿模板按钮改成「模板」：单击下拉、长按编辑**
  - 按钮文字 `写稿模板` → `模板`（`Name=TemplateButton`）。
  - **单击**：弹出下拉列表，列出模板名称（附步数）；列表底部固定一行说明 `长按模板按钮可以修改模板`（不可点）。
  - **长按 800ms**：打开模板编辑弹窗——左侧模板名称列（新建 / 删除），右侧是当前模板的详情（模板名称 + 子任务表：剩余 % / 子任务 / 下一步动作，可加行删行）。保存时百分比不合法会自动摊平成递减序列，不用手算；名称留空或没有任何子任务会当场提示。
  - 模板持久化：`AppData.Templates`（新字段，随 `data.xml` 一起备份/同步）。老数据文件没有这个节点时，字段初始化器自动给出内置「写稿」模板；用户清空后保存的空列表会被如实读回。
  - `TemplateLibrary` 提供内置模板、深拷贝（载入项目时复制，改项目不会改模板）、百分比归一化。
  - 在任务编辑页改模板会立即落盘（`ProjectDialog` 收到 `persist` 回调，MainForm 传 `Save`），取消任务编辑也不会丢模板修改。
- **回归**：
  - 逻辑单测：新装即带「写稿」模板；模板能存取往返；`Normalize` 修好非法序列且不动手调好的序列；`Clone` 不共享对象。
  - 界面单测：模板按钮文字、下拉项数与底部提示、选中模板后 6 步百分比仍为 100/90/80/70/20/15、模板编辑弹窗左右两栏内容；`今日已专注：00:10:00（02:10:00）`（今天 10 分钟 + 昨天 2 小时）、从未开始的项目显示 `项目总专注：00:00:00（今日没有记录噢）`。

## 2026-09-14 · 提前完成的步骤不再在原定时间点弹窗（TIMER-004）

用户反馈：挑战模式下提前勾掉前几步，到这些步骤的原定时间点仍会弹出「已完成当前路径点」并暂停计时，提醒下一步。

- **根因**：挑战的阶段提醒由 `FocusEngine.Tick` 里的 `stageIndex` 按「逻辑时间越过计划边界」推进；而提前完成（子任务清单勾选、mini 勾选）只把 `Stage.Done=true`，`stageIndex` 不动。时间越过原定边界时，引擎仍把早已完成的步骤当作「刚到达」，触发 stage 弹窗并暂停。
- **改动**：
  - `src/Model.cs`：`Tick` 推进 `stageIndex` 时跳过 `Done` 的阶段——提前完成的步骤不再触发 stage 事件；后续未完成步骤仍在各自原定边界提醒，总挑战时长不变（与「提前完成」弹窗承诺的「后续原定节点不变」一致）。
  - `src/MainForm.cs`：番茄钟模式下，子任务清单勾选/取消勾选后调用 `RefreshStageDeadline()`（对齐「完成当前一步」「撤回上一步」路径），提醒跟随当前未完成步骤的截止点，修掉番茄钟下的同类旧时间点弹窗。
- **回归**：`Tests.cs` 新增 6 条断言（提前完成的步骤在老边界保持专注不弹窗；只提前一段时，下一段仍在自己的边界弹窗且 `Reached` 只含未完成段；提前完成不改变总挑战时限）；`UiTests.cs` 新增番茄钟勾选后提醒重新对准下一步的断言。登记 `docs/事故与回归映射.md` TIMER-004。
- **验证**：`powershell scripts/test.ps1` 通过（逻辑 168 断言 + 界面单测）；`build.ps1` dev 产物构建通过。

## 2026-09-08 · dev 数据隔离（数据目录与同步配置分离）

- **问题**：`src/Program.cs` 把数据目录写死为 `%LocalAppData%\LittleFocusDesktop`，而 `build.ps1` 只做了 exe 的分支命名。结果是 dev 版与正式版读写同一份 `data.xml` 和 `sync.xml`；在 dev 上测试 WebDAV 同步，会通过 `DataMerge` 把测试记录双向合并进正式数据。
- **改动**：
  - `scripts/build.ps1`：非 main 分支编译时注入 `/define:DEV`（与已有的分支命名同源判定，读 `.git/HEAD`，不依赖 git CLI）。
  - `src/Program.cs`：`#if UI_TEST` > `#elif DEV` > 默认正式目录；dev 走 `%LocalAppData%\LittleFocusDesktop-dev`，`sync.xml` 随目录一并隔离。
  - `src/MainForm.cs` / `src/MiniTimer.cs`：窗口标题、托盘提示、迷你计时条改用 `Program.AppName`，dev 版显示 `专注小站 (dev)`。
- **原因**：exe 分开但数据不分，等于「两个门牌、一个房间」——测试动作会直接落在真实数据上。
- **附带清理**：删除临时脚本 `_fix_garbled.py`。该脚本针对一个并不存在的「乱码文件名」：已扫描全仓库 6 个提交、所有分支、索引与磁盘，非 UTF-8 路径数为 0；git 显示的 `\345\210\206` 是 `core.quotepath` 的八进制转义，属显示转义而非存储乱码。
- **验证**：dev 构建 `FocusStation-v2.0.10-dev.exe` 内含 `LittleFocusDesktop-dev` 与 `专注小站 (dev)`；以 main 分支配置构建仍产出 `FocusStation-v2.0.10.exe`，数据目录保持正式路径，未受影响。
- **注意**：dev 版首次启动数据为空，不会自动复制正式数据；需要带真实数据复现时手动复制 `data.xml` / `sync.xml` 到 dev 目录。
