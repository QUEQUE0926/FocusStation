# 假设清单 / 风险登记表

> 对应手册 0.2：三列表格 = **假设 / 怎么验证 / 如果错了系统怎么表现**。这是产品的风险登记表，从第一天开始维护。
> 整理日期：2026-09-08 ｜ 基于 `src/` 代码现状提炼。

| # | 假设 | 怎么验证 | 如果错了，系统怎么表现 |
|---|---|---|---|
| A1 | AI 接口可超时（约 60s），且可能不可用 | 单元测试/集成测试断言"AI 挂了主计时照常、原内容保留" | fail-open：鼓励/接续建议不可用，但计时与数据不受影响 |
| A2 | WebDAV 同步服务端支持强 ETag / `If-Match` | 同步测试断言 404/412 重试与幂等合并 | 并发覆盖风险 → 本地 `.bak` 备份兜底，可手动恢复 |
| A3 | 数据文件 `schema_version == 1` 且结构完整 | `Store.Decode` 严格校验；损坏触发 `.bak` 恢复并保留 `.damaged-*` | 损坏则回退到上一份备份或空白数据，原文件不覆盖 |
| A4 | 单实例运行（Mutex 互斥） | 启动互斥测试 | 多实例可能同时写 `data.xml` → 原子写 + `.bak` 降低风险 |
| A5 | 本机应用无需外部调度 / heartbeat | 架构即桌面程序，无定时唤醒需求 | N/A（手册 2.2/2.3 对本产品不适用，不补） |
| A6 | API 密钥仅以 Windows 凭据加密存储，绝不入库 | 测试断言"磁盘上无明文密钥、备份不含凭据" | 泄露风险（已通过设计规避；若被绕过需轮换凭据并清历史） |
| A7 | 三个 policy `.md` 作为资源嵌入，编译期路径固定 | `build.ps1` 资源嵌入 + 程序集资源读取测试 | 运行期读不到策略 → 相关 AI 行为降级，主功能不受影响 |
| A8 | 用户数据目录（`%LocalAppData%\LittleFocusDesktop`）可写 | 保存失败时捕获异常并提示用户 | 保存失败 → 提示"请检查数据目录是否可写"，不丢已载入内存数据 |
| A9 | 目标机有 .NET Framework 4.x，`csc.exe` 存在 | `build.ps1` 自动探测 Framework32/64 路径 | 构建失败 → 明确报错"编译失败"，不产出残缺 exe |
| A10 | `UI_TEST` 下数据落到隔离 `testdata/`，不污染真实数据 | 测试隔离目录 + 本地假服务，不碰真凭据 | 测试误写真实数据 → 隔离失败，需在 CI 校验目录边界 |

## 备注

- A5、A9 之外，手册中"调度双保险 / heartbeat / 多平台注册表"对本机应用**不适用**，不应为凑手册而加（见 [工程实践对照.md](工程实践对照.md)）。
- 新增假设时，在此表追加一行，并同步在相关代码处加注释引用本条编号。
