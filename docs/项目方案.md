> 整理日期：2026-09-08 ｜ 依据：《新产品开发手册：MVP → 完整版的工程实践清单》
> 适用范围：v2.0.10 现状评估 + 后续演进路线。本文与代码互锁，决策点均可在 `src/` 与 `docs/` 中追溯。

---

## 1. 项目定位与目标用户

**一句话**：一款本机 Windows 专注计时小工具，帮"容易分心、启动困难"的人把事情拆小、计时、更易开始，也更易在中断后接上。

**目标用户**：
- 有注意力管理困扰（含 ADHD 特质）的上班族 / 学生；
- 知道"该做但迟迟动不了"，需要低门槛的启动动作与中断恢复；
- 重视隐私、不愿把个人任务数据交给云端。

**非目标**：
- 不做团队协作 / 多人在线项目；
- 不做联网 SaaS、不做账号体系；
- 不做跨平台（专注 Windows 桌面，移动端不在本期范围）。

---

## 2. 核心问题与价值主张

| 痛点 | 本产品的解法 |
|---|---|
| 任务太大，不知从哪下手 | AI / 手动把任务拆成 1–5 个"2 分钟内能开始"的小步 |
| 启动难、容易卡住 | 主界面只给"下一步动作"，弱化选择负担 |
| 中断后接不上 | "接续卡"记录上次停点与下一步，降低重启成本 |
| 计时枯燥、易放弃 | 番茄钟 / 极限挑战双模式 + 休息短句 + 完成奖励 |
| 隐私顾虑 | 数据纯本机，AI/同步均为可关的可选依赖 |
| 缺乏自我觉察 | "审视自我"用历史记录归纳节奏规律（不诊断人格） |

## 4. 技术架构与栈

- **语言/框架**：C# + Windows Forms，面向 **.NET Framework 4.x**。
- **构建方式**：无 `.csproj`/`.sln`，由 `scripts/build.ps1` 调用系统 `csc.exe` 直接编译为 `winexe`；三个策略 `.md` 以**资源**形式嵌入程序集（逻辑名 `LittleFocus.*`）。
- **存储**：本机 `data.xml`（`%LocalAppData%\LittleFocusDesktop\`），`Store` 负责原子写 + `.bak` 备份 + `.damaged-*` 保留 + 损坏自动恢复。
- **状态版本**：`AppData.Version == 1`，配套 `AiDefaults.Migrate` 迁移函数，不做大爆炸重构。
- **外部依赖**：
  - AI 接口：可配置 Endpoint/Model/Key（Windows 凭据加密），超时约 60s，失败 fail-open。
  - WebDAV 同步：强 ETag + `If-Match`，404/412 重试，幂等合并。
- **并发**：单实例 `Mutex` + 原子写文件。

```
┌────────────┐   拆解/鼓励    ┌──────────┐
│  MainForm  │──────────────▶│ Planner  │──▶ 可替换 AI 接口
│  (UI 编排) │               └──────────┘
│            │   读/写        ┌──────────┐
│            │──────────────▶│  Store   │──▶ data.xml (本机)
│            │               └──────────┘
│            │   同步         ┌──────────┐
│            │──────────────▶│  Sync    │──▶ WebDAV (可选)
└────────────┘               └──────────┘
        │
        ▼
   FocusEngine (计时状态机: Idle/Focus/Paused/Break/Ready)
```

## 7. 风险与待办（按优先级）

2. **事故 → 回归映射（手册 3.1）**：现有 70+ 断言很好，但缺分区编号；建议按功能分区，新 bug 直接挂一条回归用例。
3. **文档与代码互锁深化（手册 3.2）**：README 已建索引，后续在每个非平凡逻辑点加"决策文档章节 + 事故日期"注释。
